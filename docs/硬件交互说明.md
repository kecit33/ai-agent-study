# AI 校园学习陪伴助手 · 硬件交互点说明（重点清单）

> 定位：**可选加分项**。采用 ESP32（开源硬件）+ LED + 蜂鸣器，与 Web 系统形成**双向联动**：服务端下行下发提醒/状态，开发板上行轮询学习状态。
> 未接硬件时全部接口正常返回明确原因，**不影响任何主体功能**；无需为了验收本系统而购买开发板。

---

## 一、全部硬件交互点（共 6 处）

| # | 交互点 | 方向 | 触发条件 | 接口 / 服务端函数 | 硬件表现 |
|---|---|---|---|---|---|
| 1 | **复习任务到点提醒** | 服务端 → ESP32 | 复习任务 `due_time` 到期，后台每 30s 扫描一次 | `hardware/esp32.py: check_due_tasks()` → `POST {ESP32_ENDPOINT}` (`/remind`) | LED 亮 + 蜂鸣器响 1.5s |
| 2 | **手动测试提醒** | 服务端 → ESP32 | 页面「硬件联动 → 立即下发测试提醒」 | `POST /api/hardware/test` → `notify_esp32()` → `/remind` | 同上，答辩现场可即时演示 |
| 3 | **番茄钟到点提醒**（本轮新增） | 服务端 → ESP32 | 专注计时结束并记录一次专注 | `POST /api/focus/sessions` → `focus.record_session()` → `notify_esp32()` → `/remind` | 声光提示休息 |
| 4 | **专注状态灯**（本轮新增） | 服务端 → ESP32 | 番茄钟开始/暂停结束，或页面「点亮/熄灭专注灯」 | `POST /api/focus/state` → `esp32.set_focus_state()` → `POST {ESP32}/focus` | 专注中 LED **常亮**，结束熄灭 |
| 5 | **学习状态看板上行轮询**（本轮新增，双向关键） | ESP32 → 服务端 | 固件每 60s 主动拉取 | `GET /api/hardware/status` → `esp32.hardware_status()` | OLED / 串口显示「待复习数 / 待掌握错题数 / 专注中或空闲」；有待办时 LED 短闪 |
| 6 | **通用消息下发**（预留扩展点） | 服务端 → ESP32 | 任意业务调用 | `esp32.notify_esp32(task_name, message)` | 可扩展每日打卡、考试倒计时、久坐提醒，无需改固件 |

前端「硬件联动」标签页内置同一张清单表 + 实时状态看板（`#hwBoard`），答辩时不需要翻代码即可展示。

## 二、逐点详解

### 1. 复习任务到点提醒（核心加分点）

```
用户在「硬件联动」创建复习任务（course_id / task_name / due_time）
        ↓  POST /api/review-tasks  →  review_tasks 表（notified=0）
后台线程每 30s：check_due_tasks()
        ↓  SELECT * FROM review_tasks WHERE notified=0 AND due_time<=now()
        ↓  notify_esp32(task_name)  →  HTTP POST JSON {"task","message","ts"}
ESP32 WebServer 收到 /remind  →  LED HIGH + BUZZER HIGH，延时 1.5s 后熄灭
        ↓
服务端 UPDATE review_tasks SET notified=1（避免重复提醒）
```

- 不填 `due_time` 即视为即时任务，下一次扫描（≤30s）就下发；答辩想立刻看到效果用「立即下发测试提醒」。
- 服务端实现：`hardware/esp32.py`；调度入口：`server.py` 的 `_scheduler()`（Flask 版 `app.py` 同样具备）。

### 2. 手动测试提醒

`POST /api/hardware/test` 请求体 `{"task_name":"复习第3章","message":"..."}`，直接调用 `notify_esp32()`。用于无开发板时验证请求链路（返回 `{"sent":false,"reason":"未配置 ESP32_ENDPOINT..."}` 即为预期）。

### 3. 番茄钟到点提醒

`POST /api/focus/sessions` 记录一次专注（`focus_sessions` 表：minutes / course_id / note / created_at），并在完成时调用 `notify_esp32("专注结束")`。与第 1 点复用同一 `/remind` 端点，固件无需改动。

### 4. 专注状态灯

`POST /api/focus/state` 请求体 `{"active":true,"minutes":25}`：
- 写 `settings` 表 `focus_active` / `focus_since`；
- `_push_focus()` 把 `ESP32_ENDPOINT` 最后一段替换为 `/focus` 并 POST；
- 固件 `handleFocus()` 解析 `active`，`digitalWrite(LED_PIN, active ? HIGH : LOW)`。

状态会同步反映到第 5 点的看板（`focus_active` 字段），即 Web / 服务端 / 开发板三处一致。

### 5. 学习状态看板（上行，形成双向闭环）

```
ESP32 每 60s  GET {SERVER_BASE}/api/hardware/status
   ← {"pending_tasks":2,"unmastered_wrong":5,"focus_active":true,
      "focus_since":"...","server_time":"...","display":"待复习 2 | 待掌握错题 5 | 专注中"}
   → Serial 打印 / 可扩展 OLED 显示；pending+unmastered>0 时 LED 短闪 150ms
```

`hardware_status()` 用参数化 SQL 统计 `review_tasks`（未提醒）、`wrong_questions`（未掌握），并从 `settings` 读专注状态。Web 端「刷新状态」按钮展示同一数据，便于对照演示。

### 6. 通用下发扩展点

`notify_esp32(task_name, message)` 只依赖 `ESP32_ENDPOINT`，任何新业务两行代码即可接入；固件 `/remind` 已支持自定义 `message` 字段。

## 三、固件端点与接线

`hardware/esp32_firmware.ino`（Arduino-ESP32）：

| 端点 | 方法 | 请求体 | 行为 |
|---|---|---|---|
| `/remind` | POST | `{"task":"...","message":"...","ts":"..."}` | LED + 蜂鸣器 1.5s |
| `/focus` | POST | `{"active":true,"minutes":25}` | LED 常亮 / 熄灭 |
| （上行）`{SERVER_BASE}/api/hardware/status` | GET | — | 每 60s 拉取学习状态看板 |

默认引脚（可在固件顶部修改）：`LED_PIN`、`BUZZER_PIN`，`setup()` 中 `pinMode(..., OUTPUT)` 并初始化低电平。需填写 `SSID` / `PASS` / `SERVER_BASE`（服务器地址，如 `http://192.168.1.10:5000` 或线上域名）。

## 四、配置与演示步骤

1. 烧录固件到 ESP32，串口监视器记下开发板 IP。
2. 在项目 `.env`（复制 `.env.example`）配置：`ESP32_ENDPOINT=http://<开发板IP>/remind`。
3. 启动服务：`python server.py`（或双击 `start.bat`）。
4. 打开「硬件联动」页：
   - 「立即下发测试提醒」→ 开发板声光 1.5s；
   - 「点亮专注灯」→ LED 常亮，「熄灭专注灯」→ 熄灭；
   - 「刷新状态」→ 看板显示待复习数 / 待掌握错题数 / 专注状态，与串口输出一致；
   - 到「学习概览」启动番茄钟 → 结束时自动声光提醒，专注期间 LED 常亮。
5. 无开发板时：以上接口仍返回结构化结果（含 `sent:false` 与原因），Web 端状态看板照常工作，可完整演示接口设计。

## 六、答辩可用的三个亮点

1. **不是单向推送，而是双向闭环**：既有服务端下行提醒，也有开发板上行轮询学习状态，开发板相当于桌面「学习状态屏」。
2. **学习行为与硬件状态绑定**：番茄钟一开始，Web 概览、服务端 `settings`、开发板 LED 三处状态同步，比单纯「到点响铃」更贴近陪伴场景。
3. **可选、不绑架主体**：硬件全部走环境变量开关，缺失时功能不降级、师生无需任何额外设备即可验收。
