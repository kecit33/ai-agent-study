② 核心使用场景：从进入应用到用上 AI 陪伴

1 进入应用学习概览确认课程与复习状态打开
→
2 绑定课程资料把课件 / 笔记存入指定课程打开
→
3 切课验证隔离切换课程，确认资料不串课打开
→
4 发起课程内提问数据结构的资料拼入上下文打开
→
5 观察反馈与回退忙碌态、回答卡、fallback 标记打开
→
6 形成复习闭环错题分析 → 掌握 → 计划任务打开
→
杀手功能走查要点：在第 2 步把资料存入「数据结构」，第 3 步切到「高等数学」确认资料不跟随，第 4 步回到「数据结构」提问，回答只引用该课程资料；无密钥时第 5 步出现演示模式与 fallback 标记。

后台管理原型边界（不额外假设）

作业原文要求「前台应用与后台管理原型」，未要求「独立后台站点」。M01 – M05 只重组 V1.5.0 真实存在的管理操作与 REST 路由，与前台同源；不虚构登录、权限、用户管理、多租户或统计大盘。系统按单机单用户设计，暂无登录与权限。

版本边界（不画大饼）

无真实厂商 API Key，演示模式是规则化应答而非大模型推理；课程记忆为全文拼接，不是检索增强；ESP32 未实机联调（F37 不列入验收）；长文档记忆与多用户属愿景中的未来期望，不是 V1.5.0 已实现能力。

交互表达口径：墨刀 HTML 导入不保留 JavaScript，在线工程用「状态分镜 + 可点击页面链接」表达交互动作与跳转；同目录 交互走查版.html 是浏览器可直接点击操作的本地演示版，含完整状态切换与核心流程一键走查，不调用真实接口、不产生真实数据。
