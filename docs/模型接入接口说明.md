# 模型接入接口说明（文心一言 / Kimi / 自定义端点）

> 适用版本：V1.2 ｜ 后端：`server.py`（零依赖）与 `app.py`（Flask）**接口完全一致**
> 目标：拿到任意厂商的 API Key 后，**不改代码、不改配置文件、不重启服务**，即可让本系统使用其模型。

---

## 一、设计概览

```
业务层（services/*）
      │  只依赖 AgentProvider.complete()
      ▼
agents/factory.py  ── 选择当前提供商 / 自动回退演示模式
      │
      ├── agents/credentials.py   运行时密钥：环境变量 < SQLite 覆盖（输出掩码）
      ├── agents/http_client.py   标准库 urllib 请求 + 多厂商响应解析
      └── 厂商适配器
           ├─ qianfan_provider    文心一言（千帆 v2 / 旧版 WenxinWorkshop）
           ├─ moonshot_provider   Kimi
           ├─ openai_provider     GPT
           ├─ claude_provider     Claude
           ├─ custom_provider     任意 OpenAI 兼容端点
           └─ demo_provider       无密钥兜底
```

**配置优先级**：运行时写入（Web 设置页 / REST） > `.env` 环境变量 > 空（回退演示模式）。
**网络依赖**：所有厂商调用改用 Python 标准库 `urllib`，**不需要 `requests`**，本机与云端零第三方依赖即可跑通。
**失败降级**：密钥缺失、网络超时、鉴权失败、响应格式异常时，`complete()` 返回明确提示并回退内置知识库/演示模式，Web 功能不中断。

## 二、接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/agent/providers` | 列出全部可插拔模型、是否配置、配置来源、模型名与**掩码后的密钥** |
| POST | `/api/agent/credentials` | 写入运行时配置；`activate:true` 同时切换为当前智能体 |
| POST | `/api/agent/credentials/clear` | 清除某提供商的运行时配置（回落到环境变量），若为当前则回退 demo |
| POST | `/api/agent/test` | `mode:"validate"` 只校验配置不联网；`mode:"probe"` 真实调用模型做连通性测试 |
| POST | `/api/agent/complete` | 通用透传：自建系统直接调用指定或当前模型 |
| GET | `/api/status` / `/api/providers` | 原有状态接口（已同步返回 `custom` 与配置来源） |
| POST | `/api/settings/provider` | 在已配置模型之间切换当前智能体 |

### 配置字段矩阵

| provider | 必填 | 可选 | 默认模型 | 默认接口地址 |
| --- | --- | --- | --- | --- |
| `qianfan` 文心一言 | `api_key` | `secret_key`、`model`、`base_url`、`token_url` | `ernie-3.5-8k` | 旧版 WenxinWorkshop / v2 自动判定 |
| `moonshot` Kimi | `api_key` | `model`、`base_url` | `moonshot-v1-8k` | `https://api.moonshot.cn/v1/chat/completions` |
| `openai` GPT | `api_key` | `model`、`base_url` | `gpt-3.5-turbo` | `https://api.openai.com/v1/chat/completions` |
| `claude` | `api_key` | `model`、`base_url` | `claude-3-5-sonnet-20241022` | `https://api.anthropic.com/v1/messages` |
| `custom` 自建/兼容 | `api_key`、`base_url`、`model` | `secret_key`（作为额外 `X-API-Key` 头）、`token_url` | 无 | 无 |

> 说明：空字符串字段视为「不覆盖」，因此只需提交要修改的字段；要彻底清空请用 `credentials/clear`。
> **文心一言两种鉴权**：
> ① 千帆 v2（推荐）：`base_url` 含 `qianfan.baidubce.com` 或 `/v2/`，**只需 API Key**，用 `Authorization: Bearer`；
> ② 旧版 WenxinWorkshop：需要 `api_key + secret_key`，系统自动先调 `token_url` 换 `access_token`（内存缓存 30 天）再带 token 请求 `base_url`。

## 三、Quick Start

### 3.1 Web 界面（最省事）

`设置 → 模型接入` → 选提供商 → 填 API Key / Secret Key / 模型名 / 接口地址 → **保存并启用** → **连通性测试**。

### 3.2 接入 Kimi（Moonshot）

```bash
curl -X POST http://localhost:5000/api/agent/credentials \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "moonshot",
    "api_key": "sk-你的Kimi密钥",
    "model": "moonshot-v1-8k",
    "activate": true
  }'
```

可选模型：`moonshot-v1-8k` / `moonshot-v1-32k` / `moonshot-v1-128k`。
如需走代理或网关，额外传 `"base_url": "https://你的网关/v1/chat/completions"`。

### 3.3 接入文心一言（千帆 v2，推荐）

```bash
curl -X POST http://localhost:5000/api/agent/credentials \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "qianfan",
    "api_key": "你的千帆APIKey",
    "model": "ernie-4.5-8k",
    "base_url": "https://qianfan.baidubce.com/v2/chat/completions",
    "activate": true
  }'
```

### 3.4 接入文心一言（旧版 WenxinWorkshop）

```bash
curl -X POST http://localhost:5000/api/agent/credentials \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "qianfan",
    "api_key": "你的APIKey",
    "secret_key": "你的SecretKey",
    "model": "ernie-3.5-8k",
    "token_url": "https://aip.baidubce.com/oauth/2.0/token",
    "base_url": "https://aip.baidubce.com/rpc/2.0/ai_custom/v1/wenxinworkshop/chat/completions",
    "activate": true
  }'
```

### 3.5 接入任意 OpenAI 兼容端点（自建网关 / Ollama / 其他国产模型）

```bash
curl -X POST http://localhost:5000/api/agent/credentials \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "custom",
    "api_key": "随便填或填真实密钥",
    "model": "qwen-plus",
    "base_url": "http://127.0.0.1:11434/v1/chat/completions",
    "activate": true
  }'
```

只要对方接收 `{"model": "...", "messages": [...]}` 并返回
`{"choices":[{"message":{"content":"..."}}]}`（或文心旧版 `{"result":"..."}`）即可。

### 3.6 连通性测试与状态查询

```bash
# 只检查配置是否齐全，不联网
curl -X POST http://localhost:5000/api/agent/test \
  -H "Content-Type: application/json" \
  -d '{"provider":"moonshot","mode":"validate"}'

# 真实调用一次模型
curl -X POST http://localhost:5000/api/agent/test \
  -H "Content-Type: application/json" \
  -d '{"provider":"moonshot","mode":"probe"}'

# 查看全部模型状态（密钥仅返回掩码）
curl http://localhost:5000/api/agent/providers
```

`probe` 成功返回示例：

```json
{"ok": true, "provider": "moonshot", "label": "Kimi (Moonshot)",
 "reply": "连接成功", "latency_ms": 72,
 "model": "moonshot-v1-8k", "base_url": "https://api.moonshot.cn/v1/chat/completions",
 "configured": true}
```

### 3.7 自建系统直接调用模型（透传接口）

```bash
curl -X POST http://localhost:5000/api/agent/complete \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "qianfan",
    "system_prompt": "你是校园学习陪伴助手，回答限定在高等数学上册范围内。",
    "messages": [{"role":"user","content":"讲解夹逼准则"}]
  }'
```

也可省略 `messages` 直接传 `message`，省略 `provider` 则使用当前激活的模型。
返回包含 `reply / provider / requested_provider / model / fallback / latency_ms`；
`fallback:true` 表示目标模型不可用、已回退演示模式，业务侧可据此提示用户。

### 3.8 清除配置 / 切回演示模式

```bash
curl -X POST http://localhost:5000/api/agent/credentials/clear \
  -H "Content-Type: application/json" -d '{"provider":"moonshot"}'

curl -X POST http://localhost:5000/api/settings/provider \
  -H "Content-Type: application/json" -d '{"name":"demo"}'
```

## 四、与学习资源包联动

所有 `/api/study/*` 接口都接受可选 `provider` 参数；当该模型已配置好密钥时，
系统在内置知识库结果之上**追加模型原创内容**，并把 `source` 标记为 `hybrid(knowledge_base + llm)`：

```bash
curl -X POST http://localhost:5000/api/study/quiz \
  -H "Content-Type: application/json" \
  -d '{"subject":"高等数学上册","chapter":"ch1","count":4,"provider":"moonshot"}'
```

- 题目：`origin: "llm"` 的条目由模型生成，`origin: "knowledge_base"` 的条目带校验过的标准答案；
- 总结 / 文章：追加「AI 增补摘要 / AI 导言」，并标注所用模型；
- 思维导图：模型可补充知识节点，SVG 自动重绘；
- 模型未配置、超时或返回非预期 JSON 时静默回退知识库，**接口永远返回可用内容**。

## 七、故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `probe` 返回 `未配置密钥` | 必填字段缺项 | `GET /api/agent/providers` 看 `reason`；补齐后重新调用 credentials |
| `上游返回 HTTP 401 / 403` | Key 无效、模型未开通、额度用尽 | 到厂商控制台核对 Key 与该模型的开通状态 |
| `网络不可达` / 超时 | 服务器出网受限、地址写错 | 检查 `base_url`，校内可改走自建网关（`custom`） |
| `上游响应不是合法 JSON` | 网关返回 HTML 错误页 | 用 `curl` 直接请求 `base_url` 确认返回体 |
| `响应缺少文本内容` | 响应格式非 OpenAI 兼容 | 改用 `custom` 并指向兼容网关，或提 issue 补充解析分支 |
| 文心旧版提示 `获取 access_token 失败` | API Key / Secret Key 不匹配 | 建议改用千帆 v2，只需 API Key |
| 有回复但内容像演示模式 | 模型调用失败已自动降级 | 看 `fallback` 字段与回复开头的「接口调用失败」提示 |

## 八、安全边界（答辩如实说明）

1. 密钥保存在服务端本地 SQLite（`provider_credentials` 表），**列表接口只返回掩码**，不写日志、不进前端 localStorage。
2. 当前 `/api/agent/*` 未做登录鉴权，适合校内演示与本机验收；**公网部署生产化前必须加鉴权**（例如反向代理 Basic Auth、Token 或接入统一身份认证），否则任何访客都可能改写模型配置。
3. 本系统当前为**演示/验收用途，无多用户体系**，所有访客共享同一份模型配置与课程数据。
4. 模型输出内容由第三方产生，系统已通过知识库接地与来源标注降低幻觉风险，但**不保证模型生成题目的绝对正确性**；内置知识库题目均附校验过的标准答案与解析。

## 九、自测如何覆盖

`docs/study_check.py` 会在本机临时启动一个模拟「OpenAI 兼容端点 + 文心 OAuth/聊天端点」，
通过本接口写入密钥并真实发起调用，因此**无需任何真实 API Key** 即可验证完整链路：
鉴权头、token 换取、请求体、响应解析、模型出题、思维导图增补、失败降级与配置清除。
把模拟地址换成官方地址、把假 Key 换成真 Key，即为真实模型调用。

本地执行：

```bash
python server.py
python docs/study_check.py     # 36 项断言，输出 docs/study_results.json 与自测报告
```
