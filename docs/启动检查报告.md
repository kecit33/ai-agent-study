## 一、现象与根因

用户看到的是"页面能打开、功能却全挂"，而不是传统的"进程起不来"。诊断记录如下：

| # | 实测证据 | 结论 |
|---|---|---|
| 1 | `netstat` 显示 `0.0.0.0:5000` 被 PID 43188（`python3.exe server.py`）占用，`5099` 被 PID 47192 占用 | 存在两个未关闭的旧服务进程 |
| 2 | 5000 的 `/api/status` 只返回 **5 个厂商**、无 `configured` 字段；5099 返回 6 个厂商 | 两个进程都是**修改前启动的旧代码**（Python 进程加载的是内存里的旧路由表） |
| 3 | 5000 的 `/api/study/catalog` 与 `/api/agent/providers` 均 **404** | 旧后端没有 V1.2 的路由 |
| 4 | 5000 的首页 HTML **却包含** `panel-study`、`agentProvider`、`studyPack`、11 个标签 | 静态 HTML 是从磁盘实时读取的，已是 V1.2 |

**根因 A（主因）**：旧版本后端常驻 5000 端口，前端页面却被更新成新版，形成「**新页面 + 旧接口**」的错配。用户点击「一键生成全套」「模型接入」等按钮时全部 404，看起来就像"网站没启动 / 用不了"。而 `launch.py` 旧逻辑只判断 `/api/status` 是否返回 200，误判为「服务已在运行，直接开浏览器」，进一步掩盖了问题。

**根因 B（隐藏更深）**：实测再启动一个 `python server.py`，它竟然**又成功绑定了 5000** 并打印"已启动"。原因是 Windows 下 `HTTPServer` 默认开启 `SO_REUSEADDR`，允许第二个进程绑定同一端口，于是 `bind()` 不抛 `OSError`，任何"端口冲突就顺延"的逻辑都会被绕过；两个进程同时监听，请求随机落到新旧进程上。这解释了为何问题是**间歇性**的。

**根因 C（次要）**：本机 `flask / flask-cors / requests / dotenv` 均未安装，且 `pip install flask` 因代理 `502 Bad Gateway` 失败。若按 README 方式 B 执行 `python app.py`，会直接抛 `ModuleNotFoundError` 堆栈，用户也会认为"启动不了"。

## 二、修复内容

| 文件 | 改动 |
|---|---|
| `version.py`（新增） | 单一版本源 `APP_VERSION = "1.2.1"`，两个后端与启动器共用 |
| `server.py` | `/api/status` 增加 `app` / `version` 指纹；新增 `_port_in_use()` 主动 TCP 探测（绕过 `SO_REUSEADDR` 陷阱）；`_bind_server()` 本地默认自动顺延端口、显式 `PORT`（云端）严格绑定；绑定失败打印中文排障指引而不是堆栈 |
| `launch.py` | `probe()` 先做 TCP 探测，再用 `/api/status` 的 `version` 区分 `ok / stale / foreign / free`；遇旧版或异种服务自动顺延端口并提示；打印实际访问地址；捕获启动异常并输出 traceback |
| `app.py` | Flask 依赖缺失时打印中文引导（"请改用 `python server.py`"），不再抛裸堆栈；`/api/status` 同步增加版本指纹 |
| `docs/startup_check.py`（新增） | 一键启动自检：版本指纹、首页、静态资源、全部关键 GET/POST 接口共 26 项检查，输出 `docs/startup_results.json` |
| `README.md` | 重写方式 0 说明，新增「启动排障」表格与自检命令；标注 Flask 版依赖不可用时走零依赖入口 |
| `start.bat` | 无需改动：它会调用 `launch.py` 并 `pause`，修复自动生效 |

设计约束：云端 Render / PythonAnywhere 由平台注入 `PORT`，此时**严格绑定**，不会因自动顺延导致健康检查指向错误端口；仅本地默认启动（无 `PORT` 环境变量）才顺延。
